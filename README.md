# 클리닉 데모 사이트 (포트폴리오)

**이 저장소는 데모입니다.** 실제로 존재하는 병원이나 의료진이 아니며, 어떤
실제 기관과도 관련이 없습니다. 서울 강남의 미용피부과라는 소재는 개발자의
기술과 실무 판단을 보여주기 위해 선택한 가상의 브리프입니다. 콘텐츠, 가격,
진료 시간, 원장 프로필은 모두 허구입니다. 실제 광고나 실제 예약 안내로
오인되어서는 안 되며, 이 코드나 콘텐츠는 어떤 의료 광고 심의도 거치지
않았습니다.

의사결정의 배경과 세부 규칙은 `contexts/` 아래 문서가 단일 소스입니다:

- [`.specify/memory/constitution.md`](.specify/memory/constitution.md) — 이
  프로젝트가 따르는 비타협 원칙
- [`contexts/project.md`](contexts/project.md) — 목적, 데모 안전 규칙, 콘텐츠
  제약
- [`contexts/architecture.md`](contexts/architecture.md) — 폴더 구조와 계층
  경계
- [`contexts/frontend.md`](contexts/frontend.md) — 디자인 토큰, 타이포그래피,
  컴포넌트 정책
- [`contexts/testing.md`](contexts/testing.md) — 테스트 정책

## 이 사이트에 없는 것들, 그리고 이유

| 없는 것 | 이유 |
| --- | --- |
| 후기·평점 페이지 | 의료법 제56조는 환자의 치료 경험을 이용한 의료광고를 제한합니다. 홈페이지 어디에도 후기, 별점, 추천 문구를 넣지 않았습니다. |
| 검색엔진 노출 (`noindex`, `robots.txt` 전체 차단) | 가상의 병원이 실제 검색 결과에 노출되어서는 안 됩니다. 이 posture는 "아직 안 됐다"가 아니라 영구적인 결정입니다. |
| `schema.org MedicalClinic` 구조화 데이터 | 구조화 데이터는 검색엔진에게 "이 사업체는 실재한다"고 기계가 읽을 수 있게 알리는 것이 목적입니다. 같은 이유로 넣지 않았습니다. |
| 실제 인물 사진(원장 등) | 소싱한 이미지 라이선스(CC0 등)는 촬영자의 저작권만 허가하며 피사체의 초상권까지 포함하지 않습니다. 신원이 특정되는 인물을 의료진으로 제시하지 않습니다. |
| 사업자등록번호·의료기관 개설허가번호 등 실제 형식의 식별자 | "명백히 가짜"로 보이는 번호라도 실제 등록번호 형식과 겹칠 수 있어 아예 넣지 않았습니다. |
| FAQ, 블로그, 예약 폼, 전후 사진 갤러리, 언어 전환 | 스펙에 없는 범위입니다. 4개 페이지(홈·시술·원장·오시는 길) 밖의 어떤 페이지도 추가하지 않았습니다. |

기술적으로는 시맨틱 구조, 올바른 헤딩 위계, 페이지별 고유 title/description
등 SEO 기반 요소를 정확히 구현한 뒤 `noindex`로 의도적으로 막아두었습니다.
"기술이 없어서 못 한 것"이 아니라 "할 수 있지만 이 프로젝트에서는 하지 않기로
결정한 것"임을 보여주기 위해서입니다.

## 실제 고객이라면 착수 전에 물었을 질문들

실제 병원 고객을 상대했다면, 코드를 쓰기 전에 아래 질문에 먼저 답을 받았을
것입니다. 데모에는 답할 고객이 없으므로 각 항목은 `contexts/project.md` §7에
문서화된 기본값으로 대체했습니다.

1. 부작용 문구는 누가(의료진/법무) 최종 검수하나요? — 데모는 중립적이고
   일반적인 자리표시 문구를 사용했습니다.
2. 사업자등록번호, 의료기관 개설자명, 개인정보처리방침 링크 등 푸터 법적
   고지 항목의 정확한 값은 무엇인가요? — 데모는 `[고객 정보]` 자리표시자로
   슬롯만 만들어 두었습니다.
3. 이 사이트에 방문자 분석(GA4 등)을 붙여도 되나요, 개인정보처리방침에는
   어떻게 반영되나요? — 데모는 noindex 사이트를 측정할 이유가 없어 분석 도구를
   붙이지 않았습니다.
4. 목표 성능 예산(LCP/INP/CLS)은 실제 트래픽 환경(예: 지하철에서의 LTE) 기준
   으로 어떻게 잡아야 하나요? — 데모는 Core Web Vitals "Good" 임계값을
   빌드 시점에 확인하는 것으로 대체했습니다.
5. 시술 카탈로그의 가격 변경 주기는 어느 정도이며, 누가 콘텐츠를 수정하나요?
   — 콘텐츠는 타입이 있는 TS 모듈로 분리해 두어, 비개발자가 가격 한 줄을
   바꾸는 정도의 편집이 컴포넌트나 도메인 코드를 건드리지 않도록 했습니다.
6. 의료광고 사전심의(의료법 제57조)를 받을 계획인가요, 받는다면 이 카피가
   그 절차를 통과할 수 있는 수준인가요? — 데모 단계에서는 답할 수 없는
   질문이지만, 실제 병원 사이트라면 카피를 쓰기 전에 반드시 확인했을
   항목입니다.

이 목록 자체가 이 프로젝트의 차별점입니다: 같은 카테고리의 다른 데모
사이트는 대개 의료법을 고려한 흔적 없이 만들어집니다.

## 명령어

```bash
npm run dev          # 로컬 확인용 — e2e 대상 아님
npm run build        # next build → out/
npm run typecheck    # tsc --noEmit
npm run lint         # eslint (jsx-a11y, 계층 경계 규칙 포함)
npm run test         # vitest run
npm run test:e2e     # playwright + axe, 빌드 결과물(out/) 대상
```

법적 고지: 이 저장소의 어떤 내용도 법률 자문이 아니며, 실제 의료기관이라면
반드시 실제 법률 검토를 거쳐야 합니다.
